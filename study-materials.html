Study kit

DevOps study materials and practice prompts

A guided set of checklists, flashcards, exercises, and beginner projects for turning the site into a practical learning path.

Four-Week Study Plan

Each week pairs reading with a small artifact a learner can produce.

Week 1

  1. Read Fundamentals.
  2. Define CI, CD, QA automation, IaC, and observability.
  3. Draw a simple pipeline from commit to production.

Week 2

  1. Read Tools Guide.
  2. Choose one tool from each delivery layer.
  3. Explain why those tools work together.

Week 3

  1. Read Architecture.
  2. Identify quality gates for a release.
  3. Create a release checklist for a sample app.

Week 4

  1. Read CI/CD Lab.
  2. Design a pipeline failure response.
  3. Present a rollback and monitoring plan.

Flashcards

Use these as quick checks after each study session.

What problem does CI solve?It catches integration issues early by validating small, frequent code changes with automated checks.
Why are artifacts versioned?Versioning lets teams trace a deployment back to the exact source, dependencies, and build output.
What makes a good quality gate?It is automated where possible, fast enough for its stage, actionable when it fails, and tied to release risk.
What is the goal of observability?To understand system behavior from production signals so teams can detect, debug, and improve software.

Practice Projects

These can be completed with any small demo application or even as paper exercises.

Pipeline Map

  • Create a diagram with source, build, test, deploy, and observe stages.
  • Add one tool and one output for each stage.
  • Mark where human approval is required.

Release Checklist

  • List pre-release checks.
  • List deployment verification steps.
  • List rollback triggers and owners.

Incident Review

  • Invent a failed deployment scenario.
  • Identify which signal detected it.
  • Write one prevention improvement for the next sprint.
